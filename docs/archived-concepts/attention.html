DIRECTION 02 / TIMELY ASSISTANCE

Know when
help helps.

A pause might mean confusion, careful work, or a deliberate change of plan. Can an assistant recognize when help is wanted, choose a useful response, and avoid interrupting unnecessarily?

ONE SUBQUESTION / WHICH OBJECT?

“What is that?”

Several objects could be “that.”

The camera shows the scene, but this example has no clue about which object the person means.

Scripted comparison · a fixation is not proof of intent

THE PROBLEM

Seeing an error is not enough.

While assembling a small object, a person might pause to check a part, intentionally skip a step, or get stuck. Each situation calls for a different response. Constant advice can make the task harder.

THE RESEARCH QUESTION

Help, clarify, or wait?

In a controlled packing or assembly study, record goals, first-person observations, requests, corrections, and outcomes. Compare assistance conditions across matched tasks. Include moments when no help was wanted.

THE REUSABLE OUTPUT

Data about useful intervention.

A proposed dataset linking context to participant preferences and actual outcomes. It could support assistance-timing models for smart glasses and visual assistants. Gaze would be a measured input, not a label for intent.

WHAT WOULD COUNT AS PROGRESS?

Useful assistance.
Fewer interruptions.

Measure task completion, successful recovery, and unwanted interruptions. Collect the participant’s judgment of timing separately from task correctness. Compare help-on-request, a simple pause rule, and a context-aware policy. Test gaze only as an optional additional signal.

Explore everyday memory

STARTING FROM EXISTING WORK

CaptainCook4D studies procedural errors, and EgoServe annotates proactive assistance. Our proposed contribution is to test participant preferences and the effects of interventions, including when withholding help works better. The gaze example above illustrates one smaller ambiguity problem.
